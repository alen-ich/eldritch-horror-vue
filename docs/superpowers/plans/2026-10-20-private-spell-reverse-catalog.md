# План реализации серверного каталога оборотных сторон заклинаний

> **Для исполнителя:** обязательный навык — `superpowers:executing-plans`. Пользователь выбрал самостоятельное выполнение в текущей сессии, затем одну независимую проверку свежим рецензентом. Шаги отмечаются флажками.

**Цель:** проверить и описать все 20 оборотных сторон заклинаний в закрытом серверном каталоге, не включая их игровые эффекты.

**Архитектура:** серверный модуль данных и отдельный валидатор не входят в общий граф экспортов контента. Описательные записи сохраняют текст, условия и порядок инструкций; они не являются интерпретатором. Существующие движок, протокол и синхронизируемое состояние не меняются.

**Стек:** TypeScript, Node.js, Mocha/assert сервера, Vitest контента, существующие Playwright-сценарии. Установлены Colyseus 0.18.5, schema 5.0.32, серверный SDK 0.18.2, Nuxt 4.5.2, Vue 3.5.42, Zod 4.6.5, Vitest 3.2.7. Новых зависимостей нет; серверный валидатор использует обычный TypeScript, а не транзитивный Zod.

**Спецификация:** [2026-10-20-private-spell-reverse-catalog-design.md](../specs/2026-10-20-private-spell-reverse-catalog-design.md). Одобрена сообщением пользователя «делай» после предоставления русской версии. План отдельно одобрен следующим сообщением «делай»; реализация выполняется по этому одобрению.

## Общие ограничения

- Текущие checkout и ветка `master`; без worktree, коммитов, push, merge и deploy.
- Сохранить существующие незакоммиченные изменения, в том числе физический инвентарь и предыдущие spec/plan. Перед исполнением повторно прочитать `AGENTS.md`, `CODEX.md`, спецификацию и текущий diff.
- Все 20 физических экземпляров, десять видов по два экземпляра; существующие ID и привязки файлов не менять.
- Только сервер хранит тексты, результаты и связи с оборотными сторонами. Ни владельцу карты, ни другому клиенту эти сведения не передаются.
- `effectStatus: "not_executable"` и готовность категории `needs_review` сохраняются. Только `backTextStatus` становится `verified` после проверки всех 20 карт.
- Нет новых команд, выполнения эффектов, раскрытия карт, новых полей состояния или ослабления защитных проверок.
- Нет нового DSL, новых сканов, зависимостей и изменений движка ради описательных данных.
- Нечитаемый текст или неразрешимое противоречие источников — основание для точечного уточнения, а не для выдуманного результата.

## Особое внимание при проверке

1. На листе некоторые печатные номера переставлены: внутренний `copy` определяется существующим ID и позицией, а не цифрой внизу оборотной стороны. Проверка соответствия — задача 2.
2. Условие «не выпало ни одной 4» относится к граням исходных кубиков, а не к числу успехов; условные инструкции внутри ветви должны оставаться текстом с явной меткой — задача 2.
3. Общая инструкция перевернуть карту следует после ветвей; сброс внутри ветви не должен исчезнуть или стать безусловным. «No additional effect» сохраняется явно — задачи 1–2.
4. Веб-сборка может содержать легальные публичные имена `spell_*_01.webp`; проверять скрытые тексты/пути/привязки, а не запрещать эти имена целиком — задача 3.
5. Снимок и переподключение не должны начать включать статический каталог или оборотную сторону владельцу; адресные ошибки также проверяются — задача 4.

## Задача 1. Контракт описательных записей и валидация

**Файлы:** создать `private-spell-back-types.ts` и `PrivateSpellBacks.test.ts` по путям выше.

**Интерфейсы:**

```ts
import type { SpellKind } from '@eldritch/content';

type SuccessRange = { min: number; max: number | null };
type SpellBackInstructionTag =
  | 'resource_loss' | 'resource_gain' | 'condition_gain' | 'discard'
  | 'flip' | 'prevention_replacement' | 'monster_damage_replacement'
  | 'monster_damage' | 'skill_improvement' | 'test_bonus' | 'reroll'
  | 'additional_action' | 'asset_gain' | 'no_additional_effect'
  | 'unsupported_mechanic';
interface SpellBackInstruction {
  text: string;
  tags: readonly SpellBackInstructionTag[];
}
interface SpellBackRecord {
  physicalId: string;
  kind: SpellKind;
  copy: 1 | 2;
  printedNumber: 1 | 2;
  sheetSlot: number;
  sourceBackSheet: 'source-assets/spells/back.jpg';
  privateAssetPath: string; // apps/server/private-card-assets/spells/<physicalId>.webp
  verifiedOn: string; // фактическая дата визуальной сверки, YYYY-MM-DD
  text: string; // весь напечатанный английский текст, включая заголовок и номер
  branches: readonly {
    when: SuccessRange;
    instructions: readonly SpellBackInstruction[];
  }[];
  afterBranches: readonly SpellBackInstruction[];
}
function validatePrivateSpellBacks(records: unknown): asserts records is readonly SpellBackRecord[];
```

Все типы экспортируются только из серверного модуля. Валидатор сверяет метаданные с `baseGameSpells`; файловая проверка существования и хешей выполняется тестами. Диапазоны включительны, `null` означает отсутствие верхней границы. Ветви идут по возрастанию и покрывают неотрицательные целые от 0 без разрывов и пересечений. Инструкции — текст с метками, без исполняемых параметров: количества, цели, «may», «unless», ссылки на кубики и замены сохраняются дословно.

Валидатор принимает `unknown`, поэтому проверить также `null` и массивы неправильной формы. Для `afterBranches` сохранить отдельный порядок.

### Независимая проверка и исправления

Использован один свежий рецензент (`gpt-6-astra`, high), без делегирования реализации. Critical не найдено. Important: первоначальный CLI не обнаруживал бинарное изображение оборотной стороны под обычным публичным именем. Ошибка воспроизведена тестом `rejects private reverse bytes copied under ordinary public filenames` (RED: отсутствовало ожидаемое исключение). Исправление: сравнивать SHA-256 каждого файла сборки и public с хешами всех 20 закрытых изображений. GREEN: проходят легальные лицевые изображения, отклоняются оборотные стороны с исходным и произвольным именем; полный набор и проверка сборки повторены.

Отложенный Minor: разреженный JavaScript-массив `tags = new Array(1)` может пройти структурную проверку из-за поведения `every()`. В фактическом статическом каталоге все массивы плотные и отдельно сверены; сетевой ввод в этот валидатор не поступает. Это ограничение не объявляется устранённым. Нового review после исправления не было: использованы воспроизводящий тест и полный набор проверок.

### Обоснованные отклонения и ограничения

- В текущей Windows-среде shell-помощники навыка рассчитаны на Bash и английские заголовки задач. Журнал вёлся штатными PowerShell-командами; постоянная запись результатов сохранена здесь.
- Системный pnpm 12.11.2 при отключении автоматического выбора версии начал переустановку зависимостей перед lint. Загрузка упёрлась в DNS sandbox. Процессы остановлены; установка восстановлена закреплённым pnpm 10.28.0 через `pnpm install --frozen-lockfile` с сетевым доступом. Lockfile и манифесты не изменены. Итоговые команды выполнены закреплённой версией. Предупреждение установки об ignored build scripts не препятствовало проверкам.
- Команда плана `pnpm test:e2e -- <path>` фактически запустила все четыре сценария. В первом прогоне Personal Assistant завершился тайм-аутом; следующий запуск пересёкся со вторым Playwright-процессом и получил ошибки общего каталога артефактов/сервера. Это ошибка организации проверки, не исправление игрового кода. Затем оба процесса завершены, полный набор и отдельный Spell-сценарий успешно выполнены строго последовательно. Исходный тайм-аут в изолированном полном прогоне не повторился; его причина окончательно не установлена.
- Проверка хешей обнаруживает побайтовые копии существующих reverse-файлов, а не любое возможное повторное кодирование изображения. Проверка текстов и графа импортов — целевые регрессии, не универсальный анализ утечек.
- Существующие предупреждения Turbo об outputs тестовых задач, Nuxt/Rollup, Colyseus SDK и цветовых переменных окружения не являются проваленными проверками.
- Сохранены исходные посторонние изменения. Нет коммитов, push, merge, deploy и новых зависимостей. Casting, реакции, starting grants, награды и Other World 1/6/20 остаются отдельной работой.
