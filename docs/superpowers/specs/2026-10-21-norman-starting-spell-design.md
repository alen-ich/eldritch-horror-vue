# Стартовое Feed the Mind для Нормана

Дата: 2026-10-21. Статус: одобрена пользователем ответом «да»; подготовка плана разрешена. Реализация требует отдельного одобрения плана.

## Цель и подтверждённый разрыв

Следующая необходимая зависимость — стартовая выдача физического Feed the Mind Норману. Это зависимость игрового потока, а не новая npm-библиотека: уже реализованный cast должен стать доступен из обычного лобби без тестовой выдачи.

Исследованы AGENTS.md, CODEX.md, архитектура vertical slice, дорожная карта, документы Reference Guide, rulebook, сыщиков, заклинаний и token encounters, текущие Norman spec/plan, изменения Git и исходники. Ветка master; существующие отслеживаемые и неотслеживаемые изменения сохраняются. Текущие изменения по заклинаниям считаются частью исходного состояния задачи.

Подтверждения по коду:

- `packages/content/src/investigators.ts`: у Нормана Feed the Mind есть только в `startingEquipment`; машинного стартового Spell ID нет.
- `packages/engine/src/index.ts`: START_GAME создаёт inventory через `createSpellInventory`, затем возвращает результат без выдачи; REPLACE_INVESTIGATOR выдаёт Assets/Clues, но не Spells.
- `packages/engine/src/spells.ts`: уже существуют физический inventory, named gain, перемешивание и консервация 20 копий.
- `packages/engine/src/spell-casting.ts` и `norman-clue-substitution.ts`: поддержаны Feed the Mind и ограниченная замена платы Уликой Рассудком Нормана.
- `packages/engine/test/spell-lifecycle.test.ts`: нынешние проверки ожидают полную колоду после setup и пустые владения при замене на Lily. Последнее остаётся верным для Lily.
- Документальная рекомендация сначала реализовать одно заклинание уже устарела: Feed the Mind реализован в рабочем дереве. Readiness нельзя использовать как доказательство отсутствия этого кода.

Фактически установлены Colyseus 0.18.5, schema 5.0.32, Nuxt 4.5.2, Vue 3.5.42, Zod 4.6.5, Playwright 1.63.0. Новые зависимости не нужны. Версии прочитаны из установленных package.json; `pnpm list` не дал результата на момент исследования.

## Подход и альтернативы

Рекомендуется узкая типизированная выдача только Feed the Mind Норману при старте и при законной замене сыщика. Использовать существующий named gain, не дублировать выбор физической копии. Это завершает доступный вертикальный путь и не включает новые эффекты.

Альтернатива — сразу все стартовые Spells: улучшает полноту setup, но вводит активные защитные и боевые эффекты без обработчиков и блокирует больше обычных действий. Отдельная следующая задача.

Альтернатива — награды Other World 1/6/20: открывает больше контента, но случайная/именованная выдача требует проверки всех получаемых эффектов и продолжений encounter. Не является минимальной зависимостью для уже готового Feed the Mind.

## Объём и исключения

Добавить проверяемую связь стартовой выдачи со стабильным front-kind ID; поддержать ровно Нормана и `spell_feed_the_mind`. Другие стартовые Spells остаются явно неподдержанными. Не парсить display strings. Валидатор должен запрещать неизвестные/дублированные ссылки и неподдержанные записи в исполняемой стартовой конфигурации.

START_GAME и REPLACE_INVESTIGATOR используют общий внутренний путь выдачи. При обычном старте Норман получает одну из двух физических копий из конечной колоды. При замене поиск идёт только по доступной колоде: нельзя отнимать копии у живых сыщиков или с побеждённых листов. Законное исчерпание даёт успешную замену без карты, как существующий named gain. Повреждённый inventory отклоняется, а не восстанавливается заново.

Не включать торговлю, награды встреч, остальные заклинания, действие Нормана, другие контексты его пассивной способности, полную готовность семейства, persistence или исправление всей исторической документации. Не добавлять debug/grant-команду в production. Не менять ветку и не создавать worktree; никаких commit/push/merge/deploy.

## Архитектура и авторитетность

Content хранит явное типизированное соответствие стартового kind; GameContent передаёт его чистому TypeScript engine. Точная форма контракта и адаптер сервера фиксируются в плане. Сервер получает личность из соединения; существующие START_GAME и REPLACE_INVESTIGATOR остаются единственными сетевыми входами. Клиент не выбирает копию, источник, RNG или получателя стартовой выдачи.

Выдача выполняется внутри существующей транзакции внешней команды и увеличивает stateVersion ровно один раз. Не сбрасывать лимиты component usage или Norman ledger при выдаче и замене. Стартовая карта не считается применённой. Сохранить порядок существующих setup RNG операций; новый named search/shuffle выполнять после создания Spell inventory. Ошибка RNG или валидации не публикует частичное создание/замену и не расходует случайные очереди комнаты; область checkpoint должна охватывать новые операции.

Missing Spell catalog при требуемой выдаче — ошибка контента, а не успешная молчаливая потеря стартовой карты. Минимальные синтетические content fixtures без объявленной стартовой выдачи продолжают работать. Старые активные комнаты не получают ретроактивных карт при восстановлении или reconnect.

## Приватность

Публична только лицевая идентичность `spell_feed_the_mind` и существующий разрешённый вид supply top. Физический ID, порядок колоды, оборот, изображения оборотов и таблицы исходов остаются на сервере. Не добавлять их в события, ошибки, синхронизируемую schema или browser bundles. Snapshot/reconnect восстанавливает текущее владение без повторной выдачи; чужие варианты решений не раскрываются.

## Критерии приёмки и тесты

1. Обычное лобби Norman + второй сыщик → START_GAME: у Norman ровно одно Feed the Mind, в колоде 19 копий, суммарно 20. Другой сыщик не получает карту. Детерминированные входы покрывают обе физические копии; не выбирать фиксированный оборот.
2. START_GAME без Norman не меняет прежние владения/число карт; существующие Mystery/Reserve/setup результаты сохраняются до новых Spell операций. Повторный start и неверный host не выдают карту.
3. Законная замена на Norman выдаёт доступную копию; замена на Lily оставляет Spell holdings пустыми. Полный/частичный дефицит, копии у коллег/на defeated sheets и отсутствие переноса старых владений покрыты тестами консервации.
4. Неизвестная ссылка, отсутствующий каталог, повреждённый inventory, ошибка shuffle, неавторизованная/устаревшая/повторная команда не меняют входное состояние, очередь RNG, версию или владение. Успех повышает версию один раз. Usage ledgers не сбрасываются.
5. Два реальных Colyseus-клиента проверяют стартовую выдачу, владельческий cast, чужой отказ, snapshot/reconnect без повторной выдачи, изоляцию комнат и front-only payloads.
6. Playwright проходит обычное production лобби без fixture gain: Norman получает карту, начинает применение, восстанавливается после reload и завершает разрешённый владельческий выбор. Не делать browser assertion зависимым от случайного успеха/оборота: проверять достижимый общий этап и допустимое завершение.
7. Существующие inventory/casting/Norman/privacy тесты проходят; семейство остаётся needs_review. Документы явно разделяют стартовую выдачу Norman и всё ещё отсутствующие стартовые Spells других сыщиков.

## Проверка и документация

После одобрения подготовить точный RED→GREEN план, затем получить его одобрение и выполнить в текущей сессии. Вести журнал отклонений. После реализации привлечь одного независимого рецензента с чистым контекстом; существенные замечания воспроизвести падающими тестами и исправить.

Финальные проверки: `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build`, `pnpm --filter server test`, `pnpm exec playwright test --config playwright.spell-casting.config.ts`, `pnpm test:e2e`, проверка приватности `pnpm --filter server exec tsx scripts/verify-spell-back-privacy.ts` после сборки, `git diff --check`. Известная из предыдущего журнала нестабильность параллельного E2E не считается исправленной; при повторении исследовать и отдельно сообщить результат serial run.

Обновить только относящиеся к задаче разделы docs/rules/base-game-spells.md, base-game-investigators.md, дорожной карты и project-owner-guide.md. Не заменять чужие изменения. На стадии спецификации проверки продукта ещё не запускались; исторические результаты не считаются текущими.
