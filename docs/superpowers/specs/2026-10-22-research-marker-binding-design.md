# Persisted Research marker binding

Goal: retain the server-selected original marker and physical Clue identity across Research pauses/restoration, and reject redirected continuations before effects. Current binder chooses the target correctly but runtime queue references have no independent saved provenance.
Architecture: private pendingLocationEncounter.researchMarkerBinding?:{markerId:string;clueId:string}, captured from validated draw selection. Pure validateResearchMarkerBinding(state:GameState,content:GameContent):string|undefined checks well-formed known identity, every remaining collect/relocate effect across nested queue branches/costs against markerId, and the live marker's exact physical token. If marker is absent, allow only no remaining marker effects (it may already have been collected); don't freeze location or decision owner. Existing Research continuation validator invokes it before commands/server restoration. Non-Research pending data must not carry this Research-only field.
Server restoration preserves an existing active binding for the same card: missing or changed binding rejects before writes. A new room cannot cryptographically authenticate a self-consistent saved snapshot; validation ensures consistency, not signed provenance. Old snapshots with no field retain existing behavior without guessed migration; this compatibility exception is explicit. Newly generated Research draws always carry the binding, including cards without a remaining marker effect.
Recommended focused optional private field follows existing continuation pattern. Alternative infer provenance from remaining queue: loses identity after effects consumed and cannot detect a consistently retargeted queue. Reject all legacy snapshots: unnecessary breaking migration. No new command, public field, UI, package, printed effect or full readiness claim. Pure engine and server authority retained; marker/token metadata stays server-side, generic diagnostics contain neither ID.
Acceptance/tests: actual draw/JSON resume captures binding and collects selected marker, rejects redirected effect or replaced live token before state/RNG use, nested branches validate, moved marker remains legal, collected marker with no references legal, legacy unbound continuation compatible. Real two-peer restore retains private binding, rejects stripping/change atomically and hides binding. Existing full checks and three serial Playwright configs pass.
Self-review: explicit compatibility/security limits and movement semantics checked; self-approved under user delegation. Current branch/inline, preserve dirty files via exact applied deltas. Installed Vitest3.2.7 and Colyseus0.18.5 suffice.
